# 1000节点性能验收记录

当前 Ubuntu 虚拟机、Yosys 0.69 v14 和本记录的八类固定种子用例：性能与功能验收通过。

- 环境：Linux `6.8.0-138-generic`，8个逻辑CPU；CPU报告为 `Intel(R) Core(TM) i7-14700HX`，虚拟机 MemTotal 为 `3961292 kB`。
- 仓库提交：`c9b5d9c8ec95605c672dd79185b8c5545ca3da83`；验收脚本 SHA-256：`f8febab5a8999c237dbab63a4f537b5df6ee80c814c698e6455b11c224ddc1f7`。
- 每类原版与候选版各启动3个独立进程，交替顺序，共48次完整综合；使用最大值判定。
- 计时范围为读取 RTL、完整 synth_intel（包括 ABC）及网表输出；测试准备、测量服务启动和形式验证不计入优化时间。
- 规模同时检查优化前 RTLIL cell 数和原版默认综合后的总 cell 数，二者均≤1000，每例至少一种口径达到950～1000；该口径不等同于主办方未明确的“节点”定义。
- 候选版最大耗时：**1.910945秒**，限值60秒。
- 内核 cgroup 整体计费内存峰值：**39.168 MiB**；含监测 Python、Yosys、ABC 及其子进程。
- 同时 RSS 的保守上界最大为 **413.895 MiB**；两种内存检查均≤2,000,000,000字节，禁用测试服务的交换空间，无 OOM 或进程数限制事件。
- RSS 上界取内核进程最高 RSS 乘以任务峰值（内核未提供任务峰值时使用已验证的16任务上限），所有后代均等待回收。此值是保守上界，不是实际峰值。
- 所有新用例为组合逻辑：原版、候选版分别对源 RTL 进行 SAT 等价证明，共16项通过；故意错误输出的负对照成功检出反例。两子进程各分配64 MiB 的正对照确认子进程合并内存计量。
- 此结论适用于当前环境及列出的结构；不能保证所有≤1000节点电路或替代官方 eLinx 验收。已有四个公开用例的 EQY 证据另存。
