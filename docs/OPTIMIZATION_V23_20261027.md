## 1. 问题及可复用结构

原算术共享在 PMUX 所有分支均为同类、可安全移除的全宽运算时，把多份 add/sub 改为“先选择两侧输入，再共享一份运算”。v21 对 `$add` 已按无序操作数对统计独立运算数量，但保留每个分支原有 A/B 方向。方向不同会改变两组输入选择树可以共享的子节点数量。

九例中并没有发现“所有加法分支存在同一公共操作数，仅因方向不同而漏检”的确定实例。实际结构机会在 crossbar 的循环加法表：

```text
选择码        0       1       2       3
原表达式     a+b     b+c     c+d     d+a
原输入 A      a       b       c       d
原输入 B      b       c       d       a
一种等价 A    a       c       c       a
一种等价 B    b       b       d       d
```

相同位宽和相同有符号属性下，各分支逐码交换加法输入保持结果。按自然顺序建立两组输入的联合位选择 DAG，上表原方向每位需要五个 mux 节点，所示方向每位四个。五位实例的结构成本为 25→20。该数字是输入选择图节点数，不是最终 LUT 数，也不能单独作为采纳后的面积验收。减法不具有该交换律，因此不搜索 `$sub` 方向。

这是一种按运算语义和图结构进行的通用优化；源码没有识别测试名称、路径或输入输出名称，也没有运行探测综合、ABC 或按用例切换脚本。

## 2. 实现及原保护条件

源码身份为 `selected-v23-add-orientation.cc`，SHA-256：

```text
62b6e92eef39be4b80e91ab2d0effd8a9550aa9083ce55f5844796956857db49
```

新增 `pmux_input_dag_nodes` 和 `choose_add_orientation` 两个纯内存 helper（源码第 17、64 行），调用点在第 286 行附近。v21 原有的以下准入条件先完整通过，才尝试方向搜索：

- 仅匹配相同控制向量的互斥、唯一二进制等值译码分支，控制位数仍为 2～6。
- 原默认值、分支和运算输出位宽一致；算术 A/B/Y 的完整位宽一致，宽度至少四位。
- 同组算术类型和各 A/B 有符号属性一致；运算输出只能用于目标 PMUX，保持选择范围、单驱动、无环及 keep 保护。
- 不使用常量/重复位等明显低成本算术来夸大共享收益；至少两个独立运算。原保守 LUT 收益估算先达到既有门槛。
- 算术默认值为字面 X 时，原先的“等值分支完整覆盖全部二进制控制码”要求保持。没有使用 reset、enable 或状态可达性假设填充缺失控制码。

在这些条件之上，新增搜索仅限 `$add` 且 `A_SIGNED == B_SIGNED`。非 X 默认也计为一个 value；总 value 数最多八个。每一个真实选择码按原 `select` 与 `decode` 的对应关系映射到具体 A/B 输入，不能把源码分支顺序当成二进制码顺序。未列出的码仍逐字使用原默认输入；字面 X 也按原值保留。

所有方向均使用同一个自然 selector 次序计算联合 DAG：消除 A==B 的节点，并在两个输入、所有输出位之间用 `(selector, low, high)` memo 共享相同子树。方向零是原方向；只有严格更低的节点数才更新，原方向与最优成本相同时保留原方向。固定第一个 value 不交换，因为整体交换共享加法器的两侧不会改变联合 DAG 节点集合；这样可消除全局对称的一半枚举。

选定方向后重新计算 `common_a/common_b`、输入 PMUX 数及原收益公式。如果新方向不再满足原收益门槛，回退原方向。原独立加法数量已按无序操作数对统计，交换方向不会改变该数量。除选择的数据向量外，原控制、运算类型、删除条件及后续 bitwise/sub 路径不变。

方向启发式完成后，已有共享树阶段仍对当前控制位的全部排列求最小节点图，最多六位、720 个排列。方向搜索没有穷举“方向×selector排列”的联合全局最优，也不保证自然次序下减少的节点一定对应最终 ABC LUT 减少；最终结果以重新完整综合和形式证明为准。

## 3. 复杂度和成本上界

设 value 数为 n、数据宽度为 W、控制位数为 k。方向数 `D=2^(n-1)`，上限 128。每个方向对两组输入、W 个输出位建立至多 `2^k` 码的递归图；按 `std::map` memo 计，时间约为 `O(D·W·2^k·log(W·2^k))`，单次试验空间为 `O(W·2^k)`。

宽度没有全局固定上限，因此枚举前额外限制：

```text
D * 2 * W * (2 * (1 << k) - 1) <= 262144
```

该数约束本 helper 全部方向的递归访问量，不是总 CPU 时间的严格界，也未把叶子表构建与映射查找的常数开销写成零。超出预算或 value 数超过八时，只跳过方向启发式，仍按旧逻辑处理已准入的 factor。循环加法示例 n=4、W=5、k=2，对应 560 次递归访问预算。

## 5. 方向边界初版错误与修正证据

初版 24 项中有 23 项 PASS，`mixed_operand_signedness_orientation_skip` 在前端退出 -11，整份报告为 FAIL。定位发现 fixture 直接生成 `A_SIGNED=1、B_SIGNED=0` 的内部 `$add`，违反该版 Yosys 原生 cell 检查约束；原版 baseline 在不运行新 PMUX pass 的流程中同样退出 -11。这是非法测试输入，不能计为优化器 24 项通过，也不能将该项静默删除。

修正版 v2 只替换这一 fixture：用合法的 `$signed(a)` 与 unsigned `b` 的 Verilog 混合表达式，并检查前端规范化得到四个 `$add`，其 `A_SIGNED/B_SIGNED` 均为 0，`A/B/Y_WIDTH` 均为 5。其余 23 项不变。v2 的 24 项完整重跑及错误输出负对照通过，候选 ELF 仍为上表同一份；脚本摘要为 `7e42edea1ef70766945f8607caaf01f8806da5d5707f224dd29071c63ecc2920`。这项合法表达式测试检查实际前端语义，不据此宣称构造出了合法的内部异符号 `$add`。

初版失败报告摘要为 `aea8071998f6b46de3efe6dce5b3904e849f9a0d8faba8fde97374a16d9b8f23`；原版复现/定位报告摘要为 `fecf03f59be4eb3771437134ea252e2d38abff48ba0197fa6e1613b11f274b5a`。两者与修正版通过证据一并保留。
