## 2. 整体架构与综合调用流程

### 2.1 两版程序的比较关系

两版均基于官方 Yosys 0.69，源码基线提交为 `9f75ca1f9834a39a863915b5dae0c7b1e33533bc`，使用相同 ABC 二进制和对应平台相同的编译配置。候选版的改动包括新增 pass、构建注册、在 `synth_intel` 内调用该 pass，以及提供统一 ABC 脚本。基线不加入这些优化改动。

外部输入流程在两版之间采用同一种形状：

```text

  │ read_verilog（按文件类型可加 -sv）
  ▼
synth_intel -family cycloneiv -top <top>
  ├─ 原版：官方默认综合流程

            其余既有综合阶段继续执行

  ▼
Cyclone IV 最终网表 ──→ LUT、NOT、DFF、总 cell 统计

独立形式导出链：同一综合流程运行至 map_cells 之前
  ▼
ABC9 后的原生 $lut / dffeas ILANG ──→ 原 RTL 对网表 EQY
```

集成 patch 在 `coarse` 标签的 `proc` 后加入 `run("pmux_competition_opt")`。这一位置使 Verilog 过程语句已转换为 `$mux`、`$pmux` 等内部单元，同时仍保留等式译码与字级运算结构，便于识别。优化 pass 不自行调用其他综合器，也不试跑多个综合流程选择结果。

候选 `map_luts` 调用为：

```text
abc9 -lut 4 -W 300 -script +/intel/competition_abc_v11.abc
```

默认情形如带有 `-dff`，仍按 `synth_intel` 原有选项追加对应参数。固定脚本内容为：

```text
&dch -f; &if -K 4 -a -C 4 -F 7 -A 1
```

这里保持 4 输入 LUT 目标。参数调整属于允许的 ABC 脚本调整；没有替换 ABC 二进制或修改 ABC 源码。九例共享该脚本，不按文件名、规模或网表特征选择不同脚本。程序中的 cell 名字排序仅用于确定遍历顺序，不以用例名字选择优化策略。

## 3. 条件事实提取与数据替换

### 3.1 能提取什么事实

扫描模块内 `$eq` 和 `$logic_not`。对 `$logic_not(a)`，按 `a == 0` 建立事实。对等式，将完全常量的一侧放到 B 侧，只接受以下结构：

- 输出 Y 是一个有线信号位；A、B 位数一致。
- B 完全由已知的 0/1 构成，含 X/Z 的常量不作为事实来源。
- A 的常量位必须与 B 对应位一致；若同一有线位在 A 中重复出现，所有位置对该位的要求必须相同。

因此，选择信号 `s = (ctrl == 3'b101)` 为真时，可建立 `ctrl[2]=1, ctrl[1]=0, ctrl[0]=1`。该事实只在对应分支被选中的条件下成立，并不把控制信号全局改接为常量。

`facts` 对控制位宽没有 2～6 位限制；它可服务于只有普通 `$mux` 的模块或宽译码器。`decode` 是更严格的子集：控制宽度必须为 2～6，且事实数等于控制位数，排除控制向量中的常量位、重复位等不满足完整唯一编码的结构。只有后者用于操作数提取和共享树重建。

### 3.2 替换范围和正确性理由

对选中的、未设 cell keep 的 `$mux` / `$pmux`，检查 B 总宽度等于输出宽度乘选择分支数。逐一读取 `S[arm]` 对应的事实，只将该分支 B 中直接出现的、经 SigMap 归一后的信号位换为已知常量；不改默认输入 A，也不全局改线。

```text
for each selected non-kept mux/pmux:
    require size(B) == width(Y) * size(S)
    for each arm:
        if S[arm] has conditional facts:
            for each data bit in B[arm]:
                if canonical(data bit) is in facts[S[arm]]:
                    replace this branch bit by the implied 0/1
```

小例：`y = (ctrl == 2'b10) ? {ctrl[1], d, ctrl[0]} : other`，其真分支可改为 `{1'b1, d, 1'b0}`。当选择条件为假时仍选择 `other`；未对 `other` 施加该条件。它不需要改变优先级 mux 的选择顺序。

宽译码条件下也必须先执行这一步，再判断是否进入重型阶段。v21 的 `decode.empty() || !has_pmux` 返回位于替换之后（371～374），不会因“只含 `$mux`”或“译码宽度大于六位”而漏掉合法替换。`substituted_bits` 记录执行的位替换次数，供回归检查，不作为面积收益的替代指标。

## 4. 跨 PMUX 分支的运算共享

### 4.1 为什么需要连接关系保护

若各 PMUX 分支分别计算同一种运算，选择后再计算一个共享运算，可能减少运算单元数量。例如：

```text
原结构： PMUX(a ^ k, b ^ k, c ^ k, d ^ k; select)
候选：   PMUX(a,     b,     c,     d;     select) ^ k
```

但不能仅凭代数式相似就删除分支运算单元：其输出可能被模块输出、其他单元或选择信号共同使用，也可能存在保留属性和位宽截断。因此，`factor_pmux_operators` 先建立所有模块连接的 driver/user 索引。模块输入作为不能删除的 driver，模块输出作为额外 user；未知单元的连接保守地同时视作输入和输出。

该函数在模块具有 `keep` 属性时直接返回。对内部可改写目标，它要求目标 PMUX 和分支运算单元均被选择，且没有 cell keep。分支运算输出必须逐位满足：

- 有且只有该运算单元驱动；不是常量、别名重复位或保留线位。
- 每个位只有一个使用单元，而且必须是当前 PMUX；不能再驱动模块输出或其他单元。
- 不同时作为当前 PMUX 的选择位。
- 运算完整 Y 向量与该 PMUX 数据分支一致；A/B/Y 的端口宽度及参数宽度均等于 PMUX 输出宽度。

只有确认全部原用途已被重接后，才删除旧的分支运算单元。函数维护索引的删除/新增，避免同轮嵌套改写继续使用陈旧的 driver/user 信息。

### 4.2 译码与遍历条件

运算共享只处理 2～6 位控制向量的 equality-decoded `$pmux`：所有选择信号必须来自同一控制向量的不同编码，不能重复编码，也不能混入原始任意选择位。因此，在已定义二进制控制值下，选择分支互斥。

函数对 PMUX 目标按名字排序，再沿 PMUX/mux/XOR/AND/OR/add/sub 的 A、B 数据依赖做深度优先遍历，以便先处理内部目标，再处理其外部使用者。此阶段检测组合依赖环并跳过涉及环的 factoring 目标。触发器不在遍历的运算集合内，属于叶子；不会把跨寄存器反馈误当成组合环。这里的环检测只描述该 factoring 阶段，不表示 pass 对任意组合环电路作了完整保证。

### 4.3 XOR、AND、OR 公共操作数提取

要求各数据分支由同一种 `$xor`、`$and` 或 `$or` 产生，至少有两个不同运算单元。由于这些操作可交换，公共操作数可出现在不同分支运算的 A 或 B 侧。找到共同的完整向量后，将剩余操作数送入原 PMUX，PMUX 输出再与公共向量运算一次。

如果默认输入 A 是实际值，则它也必须来自满足同样条件的运算单元，并参加公共操作数检查。若默认 A 是整向量 X，XOR 允许省去默认运算分支，因为 `X ^ common` 仍为 X。AND/OR 对整 X 默认不做该提取，例如 `X & 0` 可能成为确定的 0，这不应在该变换中被轻率使用。混合已知位和 X 的默认值不会自动当作“整 X 默认”。

该阶段以“多个同类运算变为一个、保留一个数据 PMUX”为结构收益依据，没有运行 ABC 进行探测，也没有单独预测最终 LUT 必然减少。因此，是否满足比赛的单例逻辑非增仍由完整综合后的网表验证。

### 4.4 add/sub 字级运算共享

加减法共享保留运算方向：对于减法，A/B 不可交换。全部分支要求同一 `$add` 或 `$sub` 类型，A_SIGNED 与 B_SIGNED 参数也必须逐分支一致。复用后的共享运算显式保留这些参数。数据宽度至少四位，并要求 A/B/Y 的完整宽度一致，不跨越隐式扩展或截断边界。

每个操作数位都必须是有线位，单个操作数内部的位必须各不相同；A 与 B 不得为同一整个向量。此处是保守地避开常量、重复位和显然可简化的低成本运算，不能解释为数学意义上证明了这些位彼此独立。按不同 `(A,B)` 向量对估计需共享的运算个数；加法允许把交换的 `(B,A)` 当作同一对，减法不允许这样合并。

有公共 A 时，仅为不同 B 建立一个 PMUX；有公共 B 时反之；两侧均变化时建立两个输入 PMUX。若两侧均相同，则已有运算表达本就相同，不在这里计作新的共享收益。

小例，保持方向的减法：

```text
PMUX(base-a, base-b, base-c, base-d; select)
    → base - PMUX(a, b, c, d; select)
```

有实际默认值时，默认也必须由合格的同类运算产生。整 X 默认仅在所有 `2^n` 个二进制控制编码都有不同 equality 分支、默认在这些编码下不被选择时允许省去；不利用 reset/enable 条件或用例约束来宣称默认不可达。稀疏编码的 add/sub 整 X 默认会跳过；混合 X 默认不走该特例。

### 4.5 算术共享的成本门槛

令输出位宽为 W，显式 PMUX 分支数为 A，不同操作数对数为 I，所需输入 PMUX 数为 M（1 或 2）。代码使用整数除法估计：

```text
arithmetic_luts = W + floor((W - 1) / 2)
pmux_luts       = W * (floor((A + 1) / 2)
                       + floor((floor(A / 2) + 2) / 3))
estimated_gain  = (I - 1) * arithmetic_luts - (M - 1) * pmux_luts
执行门槛：estimated_gain >= max(2, floor(W / 2))
```

`M-1` 体现原输出 PMUX 被移走、其中一个输入 PMUX 可与其成本抵消的粗略估计。共享等式译码器没有被计入收益，避免把本来就共用的译码重复算作节省。

例如 W=8、A=3、I=4、M=1 时，估计算术成本为 11，估计收益为 33，门槛为 4。这个数只是是否尝试结构变换的门槛，并非最终将精确减少 33 个 LUT。ABC 的重写、进位映射、PMUX 分解和跨输出共享都会影响实际结果。

## 5. 完整默认表与跨输出共享决策图

### 5.1 从稀疏 equality PMUX 得到完整表

在运算共享之后，收集仍存在的、选中且未设 cell keep 的 PMUX。要求各选择信号属于同一 2～6 位控制向量，各编码唯一。建立 `table[0 … 2^n-1]`：显式编码填对应 B 数据，未列出的编码填原默认 A。只有编码全部列满时，默认值不参与这些二进制编码的输出。

例如两位控制、分支 0→a、2→b、默认→d，完整表为 `[a,d,b,d]`。这一步没有把所有缺省项武断填零，也没有把 X 改成任意有利常量；表项保留归一后的原数据位。

按完整 `SigSpec ctrl` 相等分组，同一组所有目标、所有输出位共同参与一张共享图。不同向量、不同位顺序即使可能存在语义关系，也不在该规则里自动合并。

### 5.2 按 Shannon 分解建立 bit-mux DAG

每个输出位是关于 n 个控制位的选择函数，叶子是一个原始数据位或常量；叶子不是整份 RTL 真值表，只枚举控制编码下选择哪一数据位。对一个控制位次序进行递归分解：低分支保持该位为 0，高分支置为 1，生成 `mux(lo, hi, selector)`。

```text
build(column, code, depth):
    if depth == n:
        return column[code]
    lo = build(column, code, depth + 1)
    hi = build(column, code | (1 << order[depth]), depth + 1)
    if lo == hi:
        return lo
    key = (selector[order[depth]], lo, hi)
    return memoized_or_new_node(key)
```

若 lo 与 hi 相同，省略该选择节点；若多个输出位或多个 PMUX 子树具有相同 `(selector,lo,hi)`，使用同一节点。节点只在低、高子图完成后创建，形成可直接按顺序实体化的 DAG。普通 `$mux` 中 0 选择 A、1 选择 B 的语义与这里一致。

小例：完整列 `[a,b,a,b]` 只依赖 ctrl[0]，ctrl[1] 两侧子图相同而被消去，最终只需一个 `mux(a,b,ctrl[0])`。两路输出若含有同一中间选择子图，也可复用同一 bit-mux 节点。

### 5.3 选择位排列搜索与确定性

控制位数限于 n=2～6。遍历 n! 个排列，最多 `6! = 720`，每个排列为整个控制组建立共享 DAG，以总 bit-mux 节点数为代价。只有节点数严格更小时才替换当前最优方案，平局保留首次遇到的排列，因此结果选择规则固定。

v21 将目标→输出位→控制编码的叶子列预先计算一次，先注册控制位，再按该顺序注册数据叶子。递归不再为每个内部节点分配 active_codes、lo、hi 向量，而用整数 `code` 记录已经选择的高分支。

等价条件是：order 为各控制位的一个排列；递归深度前的位已设置且后面的位尚未设置；先递归低分支，再递归高分支。这与原升序编码集合逐位分割的访问顺序相同，因此叶子编号、内部节点插入顺序、输出编号以及首次最优排列保持一致。离线整数模型对 2～6 位、常量/重复叶、多目标等 381 组输入、5,906 个排列试验进行了逐图对照，并用故意错误的高位索引确认对照程序能发现差异。

上述图一致不等于 ILANG 文件逐字节一致：`NEW_ID` 可能包含源码行号，改动源码位置会影响对象名称。v21 因此重新进行了实际输出的形式证明，未以图对照替代 EQY。

### 5.4 重建成本、复杂度及限制

每个目标原始 PMUX 的估计为：

```text
estimate(target) = target.width *
    (floor((explicit_arms + 1) / 2)
     + floor((floor(explicit_arms / 2) + 2) / 3))
```

组内相加为旧结构估计成本。使用显式分支数而非补全后的 `2^n` 个编码，避免为原本很稀疏的 PMUX 虚增基线估计。仅当最优共享节点数不大于该估计时，创建实际 `$mux`、重接原目标输出并删除原 PMUX。

若该组全部目标的输出位数之和为 S，单次排列最多考察约 `S*(2^n-1)` 个递归节点，搜索工作随 `n! * S * 2^n` 增长，memo 操作还有有序映射开销。预计算列需要 `S*2^n` 个整数；试验图的空间亦受该规模限制。n≤6 限制了指数和阶乘的控制维度，但不保证任意超宽输出或任意大型模块都在固定时间/内存内。

“bit-mux 节点数”与最终 4-LUT 数不是严格一一对应。成本门槛只是避免明显不合算结构，最终非增仍必须按完整映射网表验证，不承诺任意新电路都减少资源。

## 6. 安全条件、未覆盖语义与实现边界

| 条件 | 当前实际保护 | 不能扩大解释为 |
|---|---|---|
| 选择范围 | 改写目标限 selected mux/pmux；factoring 的 producer 也必须 selected | 没有选择任何对象也会进行全局优化 |
| blackbox | pass 入口跳过 blackbox 模块 | 为任意未知单元提供功能模型 |
| cell keep | 条件替换、factoring、共享树均跳过带 keep 的目标；factoring 还保护 producer keep | 所有标准综合阶段均不会处理 keep 对象 |
| module/wire keep | factoring 跳过 module keep，且不删除保留线上的 producer；其 driver/user 索引包含端口 | 条件替换和共享树拥有同样的 module/wire keep guard；这两阶段实际只检查目标 cell keep |
| 多用户与多驱动 | factoring 要求完整 producer 输出只由该 producer 驱动、仅被当前 PMUX 使用 | 其他阶段对任意复杂网络完成了全局单驱动证明 |
| 位宽与 signed | factoring 要求完整等宽；add/sub 保留并逐分支比较符号参数 | 支持任意混合宽度、截断、符号扩展的运算共享 |
| 优先级 | 不把普通 priority mux 当作互斥 PMUX 重排；条件替换保留选择结构 | 对任意原始 one-hot 输入直接假设互斥 |
| 默认与 X | 保留未列出编码的 A；对 X 默认采用前述分操作规则 | 在任意四态仿真、未知控制输入下都有完整验证保证 |
| 寄存器与反馈 | 自定义 pass 不创建/删除/改接触发器单元，factoring 将其作为叶子 | 最终网表 DFF 数必定相同；后续标准综合可能进一步简化 DFF |
| 成本估计 | 算术及共享树有固定启发式门槛；无综合探测 | 任意案例最终 LUT 保证不增加 |

52 项通用运算回归使用定义良好的二进制输入，并将源设计字面 X 作为 don't-care（`-ignore_gold_x`）；不应将它称为所有四态 Verilog 行为的穷尽证明。实际九例另有整设计 EQY。对任意多时钟、锁存器、存储器、新原语或复杂异步控制网络，必须扩展模型与审查后再给出新的验证结论。

## 7. 功能验证方案与证据链

### 7.1 三层验证

第一层是结构回归。52 项通用运算边界检查覆盖 XOR 交换操作数、AND/OR 默认值、整 X/混合 X、外部用户、keep、宽度不符、缺少公共操作数、嵌套 PMUX，以及 add/sub 的公共 A、公共 B、两侧变化、signed 不匹配、常量/重复位、成本边界、混合控制、原始选择信号和重复编码等。每例检查是否应发生 factoring，并将 pass 前后的设计进行 SAT 等价验证。

第二层是六项快速路径回归：无 mux、有 PMUX 但无 facts、八位译码下仍执行数据替换，以及仅有 mux、译码宽度分别为 1/3/8 的情形。它们检查替换位数、输出常量、没有多余的 factoring/共享树阶段，并进行 SAT。故意将输出改为恒零的负对照必须被检出。

第三层是九例整设计验证，原版与候选各九项，共十八项。使用完整 `synth_intel` 统计最终资源；另一运行用 `-run begin:map_cells` 在 ABC9 后、最终 Cyclone IV LUT 映射前导出原生 `$lut` ILANG，再续跑 `-run map_cells:`。检查分段续跑和独立完整流程的最终各类 cell 数一致，避免导出流程与实际资源统计流程脱节。

### 7.2 EQY 对象、模型和结果判定

gold 为原始 RTL；gate 为实际导出的 post-ABC ILANG。gate 侧先用 `lut2mux -word` 展开 LUT，再加载受审查的 `dffeas` 功能模型。模型保留动态、低有效异步 `clrn`，没有把它固定为解除复位。

在采用模型前，脚本逐个检查原生网表的单元类型和触发器控制：仅接受已支持类型；检查 `prn=1`、`aload=0`、`asdata=0`、`sclr=0`、`sload=0`，以及 d/clk/clrn/ena/q 的标量性、控制信号和允许的 power_up 参数。遇到不支持的配置报告错误，而非默默使用错误模型。

EQY 使用 SAT depth 5 和 SBY/ABC PDR 策略。输出 PASS 必须同时有正常退出和 PASS 标记；存在确切反例记录则判 FAIL；超时或未获得明确证明为 UNKNOWN，环境或版本异常为 ERROR。不会把 UNKNOWN 当作通过。

test2 另外构造恒零错误输出网表，必须出现确切 counterexample，验证链能够拒绝错误电路。负对照预期的 FAIL 是校验成功，不应计入正向证明的失败。

Linux 私有候选、Ubuntu 稳定 current 部署默认入口分别完成十八项证明；Windows 则对本次 PE 程序实际导出的十八份 ILANG 再完成独立证明。三条链各自覆盖九例两角色，不能叠加声称为 54 个不同测试用例。Windows ILANG 原始 CRLF 摘要保留，仅为 Linux 工具制作可逆换行归一副本并验证往返一致。

## 8. 性能测量设计、当前成绩与异常

### 8.1 固定测量协议

原版和候选在同一 Windows 环境运行，使用相同测量器。每例先启动原版十次预热；正式首轮按原版→候选。墙钟从 `CreateProcessW` 调用前计到根进程结束，包含程序创建、绑定 Job Object、启动、RTL 读取、完整综合、等待 ABC 和网表写出；同一次综合读取根 `yosys.exe` 的 PeakWorkingSetSize。包含 ABC 后代的 CPU 时间另行记录作辅助。

C101/C102 推荐的 `Measure-Command` 测量墙钟，本文据此将墙钟作为主判；这是一项公开的计时实施解释。较早 C26/C41 仍使用 CPU 措辞，现场应遵循官方统一口径，不能声称两种指标等价或二者都已全部过线。当前选定样本的 Job CPU 在 test1 为 **+8.75%**、balanced 为 **+17.647059%**；Windows CPU 计数有明显量化步长，本文保留这些原值，不用量化理由将其改写为通过。

这是预先固定的实现解释，不是 FAQ 对全部细节的逐字规定。C132 还要求后台统一和“杀软关闭”；脚本没有改变任何安全设置，现有证据未确认测量时杀软已关闭，因此不能声称这一环境条件已严格验收。
