## 关键问答

### 为什么公平？是否给不同测试切换脚本？

原版和候选来自同一 0.69 源码，现场两侧使用相同 GCC13/Release 参数及相同 ABC。候选只加入批准的 pass/集成和一份固定 ABC9 脚本，九例通用。不修改其它 pass 或 ABC 算法，也不做多次探测综合后择优。source、完整patch、ELF、ABC、输入、runner和meter均有摘要。

### 条件替换会不会改坏未选分支？

`ctrl==2'b10` 为真时，这个分支的 ctrl 位已知，因此只改该分支中的数据位。默认 A 和其它分支不借用这个条件；不会把 ctrl 全局接成常量。任意原始 S 向量不能假设互斥；共享树要求同一控制向量的不同 equality 编码。

### 加法方向选择与减法有何区别？

加法可交换，但还要求已通过原成本/连接保护且 A/B signed 一致。固定第一个值方向，枚举其余最多七项的交换，对联合输入 DAG 作结构估计；最多128方向，总递归访问估计超过262144则跳过。方向改变后仍过原成本门槛。减法从不交换 A/B。

### v24 为什么能提前停止搜索而不漏最优？

一个排列内的已创建图节点只增加，之后列无法减少已经计入的节点。因此当前节点数达到已有最优时，不可能取得严格更小的最终图。原选择规则只有严格改善才换优胜者，平局保留先前排列；剪枝保持这个规则。试验阶段不创建实际模块单元。55组模型检查是辅助证据，不能替代 C++ 和 RTL 验证。

### 默认 X、keep 和多用户都处理了吗？

真实缺省编码填原 A；XOR、AND/OR和加减法的整X准入不同，不作一般四态保证。factoring有额外用户、模块输出、位宽/参数及相关keep保护，减法保持方向。其它阶段与factoring的keep范围并不完全相同，不能概括为“所有阶段保护都一样”。成本模型也不保证所有未知电路最终面积下降。

### 是真正现场编译，还是从旧目录复制程序？

本轮实际调用最终包 `offline-build/build.sh`，目标此前不存在。原版/ABC使用全新对象编译约465.66秒，候选复用这一轮未变对象并增量约5.93秒，全部步骤退出0。准确说法是“本轮干净原版加候选增量”，不是两套互相独立的全量编译。新ELF和ABC与旧交付版非同字节，因此又执行了独立新测量与新证明。

### 逻辑资源怎么统计？test3为什么也算？

每例计算 `(原版LUT+NOT−候选LUT+NOT)/(原版LUT+NOT)`，九例等权平均。test3逻辑13→13、降幅0%仍参与，DFF17→12单列。原始网表和统计均保留，不把DFF变化并入逻辑降幅，也不只挑有收益的用例。

### 当前test1效率是否通过？还有哪个首轮超限？

本轮test1首轮墙钟−0.895694%、根峰值−4.968715%。test2首轮墙钟−8.355793%，但根峰值+5.390248%触发复核。追加五次的墙钟/根峰值为+2.917401%/+0.190369%；首轮加前四次为+1.238377%/+1.372043%；全部六次为+0.930163%/+1.024027%。三种复核计算都在5%内，严格首轮全通过仍为否。

历史 WSL 的 test1+3.891671%、test2墙钟+13.405479%属于另一组 ELF，不与当前字段混用。WSL 当前结果也没有证明原生 Windows 首轮延迟已解决。

### 计时和内存到底测了什么？

墙钟覆盖完整综合及ABC等待。根内存是同次内核VmHWM，不包含ABC子进程；CPU单列，不与墙钟混用。协议先十次原版预热，再原版→候选，只有按规则触发时追加五对；118记录包括90预热、18首轮、10复核，不是118个独立候选样本。没清空OS页缓存，不能称绝对硬冷启动。

14个候选样本最大墙钟0.204042865秒、根峰值34,615,296字节。这个结果只适用于本轮九例，不能证明任意≤1000节点电路的普遍时间/内存上界。

### 18项EQY是不是直接证明所有计时进程的网表？

不是。新18项EQY使用本轮相同源码、ELF、ABC在独立不计时流程导出的对象。绑定审计确认所有保留测量样本的最终资源向量一致，但18个ILANG导出并非逐字节相同；相同资源计数不等于网表语义恒等证明。应称“新功能证明与独立性能测量按工具/输入身份绑定”，不能说每个计时输出都已直接证明。错误恒零输出被明确检出反例。

### 82项边界回归是否也是这轮重新执行？

不是。82条及三组负对照是冻结v24 WSL的历史证据，本轮新重建未重复这套回归。源代码一致并不允许把旧报告换成新二进制日期。旧非法内部signed参数夹具及其原版失败被保留，canonical v2改用合法Verilog表达式并检查前端参数。

### 包是否完全自包含？还差什么？

外层工具组带两个原始归档：v24 WSL运行/源码包和v23 EQY证明runtime，另带明确companion及本轮完整证据档。操作仍要求匹配的WSL Ubuntu24/GCC13等平台前提，不是操作系统镜像。所有输出使用新目录，失败不删除。
