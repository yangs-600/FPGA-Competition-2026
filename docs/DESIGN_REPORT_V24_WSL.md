# 赛题二：Yosys 0.69 PMUX 优化设计报告（v24 WSL）

日期：2026-10-27。本文记录已实现算法、实际离线重建与本轮现场演练证据。真实姓名、学号与分工尚待团队据实填写；不代填个人贡献。工程演练完成不等于主办方已作出最终验收结论。

## 1. 目标与本轮结论

目标是在 Yosys 0.69 的 `synth_intel -family cycloneiv` 流程中减少逻辑资源，并控制完整综合的时间和根进程峰值内存。九例面积采用每例 `LUT + 独立 NOT` 降幅的算术平均，DFF 单列；不使用总 cell 加权比，也不剔除零收益用例。

本轮从最终冻结包实际执行 `offline-build/build.sh`，进入此前不存在的目录。原版与 ABC 从源码及全新对象目录构建，候选复用本轮未改对象增量编译 PMUX/集成；完整配方未修改、未联网下载、未使用 sudo。原版编译约 465.66 秒，候选增量约 5.93 秒，所有构建步骤退出码为 0。

新二进制独立完成固定性能协议和新九例×两角色的 18 项 EQY；负对照检出确定反例。九例逻辑资源均不增加，平均减少 **20.661033%**。按已披露的短用例追加五次复核解释，墙钟与根峰值内存数值门槛通过；严格首轮九例全部≤5%仍为 **否**，原因是 test2 首轮根内存增加 **5.390248%**。官方对复核解释的认可未据此获得，`overall_submission_acceptance` 保持 `false`。

## 4. 条件常量传播与共享

若 `S = (ctrl == 2'b10)`，则 S 为真时对应分支中的 `ctrl[1]`、`ctrl[0]` 分别是 1、0。可以将该分支 `{ctrl[1], d, ctrl[0]}` 改为 `{1'b1, d, 1'b0}`，但不全局固定 ctrl，也不修改默认 A。`$logic_not(a)` 按 `a == 0` 提取事实。含 X/Z 的比较常量、重复位约束冲突等不会作为合法事实来源。

条件替换先于重型阶段 guard。只有 `$mux` 或控制宽度超过六位的场景仍可做合法分支替换；2～6 位限制针对运算共享与选择树重建，不是所有条件事实的限制。

跨 PMUX 分支的运算共享要求选择位来自同一控制向量的不同 equality 编码，才能在已定义二进制输入下确认互斥。不能把任意 S 向量视为 one-hot。示例：

```text
PMUX(a ^ k, b ^ k, c ^ k; s) → PMUX(a, b, c; s) ^ k
```

删除旧运算前检查选区、端口/参数位宽、唯一驱动和使用者、额外模块输出及 keep。未知单元连接按保守方式计入使用/驱动。加减法保持 A/B/Y 完整等宽、宽度至少四位、逐分支 signed 参数一致；减法不可交换。成本模型只作准入估计，不能保证任意电路映射后 LUT 必然减少，因此仍逐例检查最终资源。

默认值处理保持明确边界：XOR 可处理整向量 X 默认；AND/OR 不做同样提取。加减法省略 X 默认要求所有二进制控制码已被不同 equality 分支覆盖。共享树的未列出控制码填原始默认 A，不擅自填零或假定不可达。SAT 对源字面 X 使用 don't-care；这不是对任意四态时序语义的无条件保证。

保护范围也不能夸大：运算 factoring 检查 module、wire、producer/目标 cell 的相关 keep；前后其它阶段主要按目标 cell keep 保护，不能声称所有阶段具有相同的全局 keep 语义。

## 5. v23 加法方向选择

加法满足交换律，但把不同分支的输入统一朝向，可能减少共享输入选择结构。该优化只作用于已经通过原有成本与连接保护的加法，且 `signed_a == signed_b`；减法保留方向。

搜索最多八个值，固定第一个值方向，枚举其余值的交换掩码，最多 `2^(8−1)=128` 个方向。全局同时交换 A/B 的联合结构对称，因此固定一项不丢掉对应等价方向。评价量是两个操作数共同构成、采用自然控制位顺序的约简 DAG 节点数，**不是**真实 LUT 数，也没有调用 ABC 试算。

总访问估计为 `方向数 × 2 × 位宽 × (2 × 编码数 − 1)`，超过 262,144 就跳过此启发式。只接受严格减少节点数的方向，平局保留原选择；修改后重新计算公共输入及收益，仍须通过原成本门槛。规范示例的联合节点数可由 25 降到 20。

旧测试曾构造 `A_SIGNED=1、B_SIGNED=0` 的非法内部 `$add`，原版也在 PMUX 前失败。现有 canonical `test_add_orientation_v2.py` 使用合法 `$signed(a)+unsigned_b` 表达式，并要求前端生成四个宽度为五、A/B 均 unsigned 的 `$add` 后再验证方向改写。旧失败记录保留，不当作保护规则通过的证据。

## 6. v24 有界选择树搜索

同一控制向量的输出列共享一张 DAG。对 2～6 位控制枚举最多 `6!=720` 个排列，约简相同 low/high 分支，并按 `(选择位, low, high)` 复用节点。真实默认值补齐后，所有列在搜索前预计算，避免反复分配不变数据。

v24 的新增变化是**单调节点下界剪枝**：单个排列试验中的节点集合只增加，不撤销已加入节点。完成一列后，若当前节点数已经达到或超过现有最优值，其余列不可能让最终节点数严格更小；可提前停止这个排列。严格改进才替换 incumbent，因此达到相同节点数时提前终止不会破坏“保留第一次最优”的平局规则。未完成的试验不进入最终选择，实际模块对象只在胜出结构确定后创建。

```text
best = 第一个完整候选
for 后续控制位排列:
    trial = 空共享图
    for 每一输出列:
        将该列加入 trial
        if trial.nodes >= best.nodes:
            放弃当前排列
    若 trial 完整且节点更少：更新 best
```

历史独立模型检查覆盖 55 组结构、9,592 个排列，并检出错误下界变体；它检查图选择/顺序一致性，不能代替 C++ 运行、RTL 形式证明或时间测量。v24 减少搜索计算，不意味着它单独解决了 Windows 首次进程创建延迟；已有 Windows 异常证据不被本轮 WSL 成绩改写。

## 8. 时间、内存及历史分界

固定协议每例先运行十次原版预热，再原版→候选首轮；原版不足一秒且首轮墙钟或根峰值超 5% 时追加五对，保留首轮及全部复核。118 条记录由 90 次原版预热、18 次首轮、10 次复核组成。源码、工具、日志、计量侧车及两个输出摘要已逐样本核对，不以重复试跑挑选最好结果。

墙钟覆盖完整综合与 ABC 等待；内存采用同次内核根进程 VmHWM，KiB×1024，**不包含 ABC 子进程内存**，且有内核计量精度限制。CPU 作为另列诊断；不能混成根内存或墙钟。首轮指协议中的第一次候选综合，不是“已清空 OS 页缓存的硬冷启动”。

|---|---:|---:|
| 首轮 | −8.355793% | +5.390248% |
| 追加五次均值 | +2.917401% | +0.190369% |
| 首轮加前四次复核 | +1.238377% | +1.372043% |

其余八例首轮墙钟与根峰值均在 5% 以内。test1 本轮墙钟 −0.895694%、根峰值 −4.968715%。14 个候选样本最大墙钟 **0.204042865 秒**、最大根峰值 **34,615,296 字节**。这些是本轮九例的观测，不能推出所有≤1000节点设计均满足 60秒/2GB，也不把“节点”擅自等同于所有 cell 统计。

## 9. 正确性与证据边界

本轮新 ELF 对每例分别完整综合并导出 ABC 后原生 RTLIL 对象，原版与候选各九项 EQY 均 PASS；错误恒零输出负对照产生确定反例。新证明报告 SHA 为 `d103dc8edf0c92b00d5d9c88d9857802983b49d01947704d53e7fe7e37d31a6d`。异步清零模型保留动态控制；超时/错误不会作为 PASS。

形式导出在独立、不计时的执行中产生。绑定审计确认它与测量使用同一源码、ELF、ABC，且所有保留样本最终资源向量一致；18 个证明导出与测量导出的 ILANG **均非逐字节相同**。资源计数相同不证明任意两张网表语义相同，因此不能说“118 个计时进程的输出对象都已直接形式证明”。本轮证据是新执行的功能证明与独立性能测量及其身份绑定。

82 项边界回归（52 运算、6 快速路径、24 canonical 方向及三组负对照）属于早先冻结 v24 WSL 二进制的已保存证据；本轮新重建未重跑这 82 项，不能换日期冒充新结果。源码模型、历史边界、新九例 EQY、独立计量各自提供不同证据。
